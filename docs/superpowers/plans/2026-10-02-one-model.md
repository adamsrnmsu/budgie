# One Model Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** plan.csv sets each person's hours, so the TUI, the CLI and perch
all quote one cost.

**Architecture:** a new pure `people_on_plan()` in `core/project.py`, the
module that holds precedence rules, rewrites each `Person`'s hours from the
plan. Each person keeps the spread they were loaded with.
- `load_snapshot`, `Snapshot.what_if` / `with_plan`, CLI `forecast` /
  `monthly` and the TUI Forecast tab all go through it.
- `Person` gains optional `spread` and `pto_days` fields with defaults, so
  perch's `Person(name, hourly_cost, hours)` still works.

**Tech Stack:** Python 3.13, click, Textual, pytest
(`~/Documents/tools/budgie/bin/pytest`, run with `PYTHONPATH=<worktree>`,
because the editable install points at the main checkout).

**Spec:** `docs/superpowers/specs/2026-10-02-one-model-design.md`
(approved 2026-10-02: "B now"). Its "Proposed" choices are taken:
- the Year/PTO/Iterations/Seed boxes are removed;
- budgie.yaml opens with `e` from the Projects tab, which step A already
  shipped.

## Global Constraints

- No UI imports under `budgie/core/` (no click, rich, textual, matplotlib).
- Nothing heavy at module scope in `budgie/budgie.py`
  (`test_startup.py`).
- Warnings are strings a person sees. They are **never** only
  `logger.warning`.
- A project without plan.csv gives identical numbers to before.
- Only the project's own plan.csv applies, never the bundled sample.
- `HoursEstimate`, `Person.hours`, `simulate`, `at_completion` and
  `evaluate` keep their signatures. Perch's `test_contract.py` must pass,
  with names only added.

## Review Focus

1. **A name in people.csv that differs from plan.csv only by case**
   ("alice" vs "Alice"). That is two people: 0 hours plus a warning, and
   "not costed" plus a warning. Both warnings are visible. Covered in
   Task 2.
2. **util_mode 0 with a plan:** the spread falls back to none and a warning
   names the person. No divide-by-zero. Covered in Task 1/2.
3. **Plain form (`name,hourly_cost`) with no plan.csv:** hours are 0, and a
   warning says why. It doesn't silently cost $0. Covered in Task 2.
4. **`what_if` adding someone who has no rate:** the plan has them, cost
   doesn't, and `warnings` says so. Covered in Task 4.
5. **The TUI opened on the bundled sample, or with `--people`:** it keeps
   today's people.csv path and sample banner, and does not crash looking
   for a Snapshot. Covered in Task 6.

### Task 1: Person carries its spread and PTO; people.csv plain form

**Files:** Modify `budgie/core/person.py` and `budgie/core/loader.py`.
Test: `budgie/tests/test_one_model.py`.

**Produces:**
- `Person.spread: tuple[float, float] | None = (1.0, 1.0)`: the
  (low/likely, high/likely) ratios. `None` means likely was 0, so no
  ratio exists.
- `Person.pto_days: float | None = None`.
- `load_people` recognises three forms:
  - **plain:** `name,hourly_cost[,under,over]`. Hours are 0 and
    spread is `(1-under/100, 1+over/100)`.
  - **util:** spread is `(low/mode, high/mode)`.
  - **hours:** the same ratios.
  - Every form reads `pto_days` into `Person.pto_days`.

Tests:
- plain with under/over gives spread `(0.9, 1.05)` and hours 0;
- a bare `name,hourly_cost` gives spread `(1, 1)`;
- util `0.8/0.9/0.98` gives `(0.8/0.9, 0.98/0.9)`;
- util_mode 0 gives spread `None`;
- `pto_days` is read;
- the util path without a plan has the same hours as today.

### Task 2: `people_on_plan`

**Files:** Modify `budgie/core/project.py`. Test: `test_one_model.py`.

**Produces:**
`people_on_plan(people, plan, year, pto=0.0, pto_by_name=None) -> tuple[list[Person], list[str]]`

- **plan is None:** people are unchanged. A warning goes out for each
  plain-form person (spread set and every hour 0): "Alice has a rate but
  no hours: people.csv gives none and there is no plan.csv".
- **In both files:** likely = `plan.allocated_hours(name, year, pto_i)`,
  low = likely × spread[0], high = likely × spread[1].
  - `pto_i` is `person.pto_days`, else `pto_by_name[name]`, else `pto`.
  - When both PTO values are present and differ, there is a warning and
    people.csv wins.
- **Spread None:** constant hours, plus the warning "Alice's util_mode is
  0, so her hours have no spread around the plan".
- **In people.csv, not in the plan:** hours 0, warning "Bob has a rate in
  people.csv but no rows in plan.csv, so 0 hours".
- **In the plan, not in people.csv:** warning "Zed is in plan.csv but has
  no rate in people.csv, so not costed".

Tests: one per row above, plus a case mismatch ("alice"/"Alice").

### Task 4: Snapshot is plan-driven

**Files:** Modify `budgie/core/project.py`. Test: `test_one_model.py`,
plus updates to `test_project.py` where expectations followed util.

**Produces:**
- `Snapshot.warnings: list[str] = []`.
- `load_snapshot` applies `people_on_plan` with `pto_by_name` taken from
  allocations.csv (`pto_overrides`).
- `Snapshot.with_plan(plan) -> Snapshot`: it re-derives `plan`, then
  `allocations`/`planned` (as `what_if` does today), then `people` and
  `warnings`.
- `what_if(plan_entries=...)` calls `with_plan` on the combined plan.

Tests:
- appending a plan row changes `load_snapshot(...).people` hours;
- `what_if` and `with_plan` move `people` hours and the expected cost;
- `what_if` with a new name lacking a rate gives a warning.

### Task 5: CLI `forecast` and `monthly` follow the plan

**Files:** Modify `budgie/budgie.py`. Test: `test_main.py`.

- After `load_people`, both commands call `_on_plan(people, year, pto)`.
  It reads the project's plan only (`_plan_for_allocations(None)`) and
  `pto_overrides` from the project's allocations.csv. It returns the
  people and prints each warning as a yellow line.
- Test: in an `init` project, appending `Bob,<date>,0` lowers the
  `forecast` total.
- Test: the sample fallback is unchanged.

### Task 6: TUI Forecast tab reads the Snapshot

**Files:** Modify `budgie/tui.py`. Test: `test_tui.py`.

- The `#controls` boxes and the Recalculate button are removed.
  `recalculate()` reads year, pto, iterations and seed from budgie.yaml
  through `_setting`, defaulting to 2026, 0, 10 000 and 42.
- With a workspace and no `--people` override, `load_snapshot` runs.
  People go through `at_completion` when there are readings, costs feed
  `simulate`, and the headline line is:
  `Budget $X · spent $Y · forecast P50 $Z · headroom $H · ● GOOD (3% chance over)`.
  - "Spent" is Σ rate × the spent hours.
  - Headroom is budget − P50.
  - The budget, headroom and stoplight parts appear only when there is a
    budget.
- Snapshot warnings go in `#forecast_banner`. Load errors are shown as
  they are today.
- The sample team or a `--people` override keeps today's path.
- Tests:
  - a project with plan + people: the headline P50 equals
    `budgie forecast`'s P50 for the same seed and iterations;
  - appending a plan row changes the Forecast total;
  - the sample still shows SAMPLE DATA.
