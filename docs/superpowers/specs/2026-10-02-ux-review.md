# Budgie UX review

Date: 2026-10-02 · Bead: budgie-10p

**Trigger:** the user wants to edit and remove rows on the Plan tab instead of
being sent to an editor. When `e` does send them to the editor, it shows
columns the TUI never explained (`util_low`, `util_high`).

**Method:** three read-only passes.
1. A first-time walk through every TUI tab, with 50 screenshots.
2. A map of every input column against what the TUI shows.
3. The journey from `budgie init` to a forecast, including the CLI and the docs.

All three passes reached the same root cause.

## The root cause: Budgie has no single model of the team

The same facts live in several files, and different screens read different
copies:

| Fact | Where it lives | Who reads which copy |
|---|---|---|
| Who works how much, from when | `people.csv` util_mode, `allocations.csv` fte, `plan.csv` fte | Forecast: people.csv. Plan, hours, emails: plan.csv. allocations: only when there is no plan. |
| Budget | `budgie.yaml` budget, `budget.csv`, `scenarios.yaml` | The yaml number wins. The scaffold writes both, so budget.csv is dead from day one. |
| Hours spent | `weekly.csv`, `actuals.csv`, allocations `hours_spent` | weekly.csv wins, silently. The scaffold's three copies disagree. |

As a result:
- The Plan tab writes to a file the Forecast tab never reads. Adding Carol,
  removing Bob, or setting someone to 5 FTE leaves the forecast unchanged.
  In the sample team project the Plan tab shows 5,360 h and the Forecast tab
  shows 6,872 h. The scaffold hides this by using the same numbers in both
  files.
- `e` from the Plan tab opens **people.csv**. `action_edit_selected` reads the
  cursor of the Inputs table, and every recalculate puts that cursor back on
  row 0 (`tui.py:503-522`, `:891`). That is why the user saw util_low and
  util_high.
- There are three totals for one team: the TUI Forecast (labour only), CLI
  `budgie forecast` (adds costs, actuals and the budget signal), and the Plan
  tab's hours.

## Ranked findings

### Severe
1. **Pressing `d` twice on any tab deletes the whole project** when Budgie is
   launched from the parent folder. On the Plan tab, `d` reads as "delete this
   row". This was reproduced. Keys are global (`tui.py:296-308`, `:643-685`),
   and the warning is drawn in success-green.
2. **Plan and Forecast are separate models** (see above).
3. **`e` ignores the current tab** and opens people.csv.
4. **Plan rows cannot be edited or removed in the TUI.** The table shows one
   row per person, not one row per CSV line, so there is nothing to point an
   edit at. The only in-TUI fix is to append a row with the same date, which
   only works because the sort is stable.
5. **The TUI never shows the budget, headroom or stoplight,** and its forecast
   leaves out costs.csv and actuals. On the same project, `budgie forecast`
   says "100% over budget" and the TUI shows a calm P50.
6. **Bad values are accepted silently:**
   - FTE of 5;
   - "alice" next to "Alice", which become two people;
   - typo names, which are never costed;
   - util of 1.5, or 80 meaning 80%;
   - "abc" in Iterations, which silently becomes 10,000.
7. **CLI input mistakes print a Python traceback** (a bad date, a wrong column,
   an empty people.csv), with no file, row or pointer to `budgie guide`.
8. **With no project selected, the Forecast tab shows the bundled sample team**
   with no banner.

### Moderate
- **Jargon is never explained in the TUI:** util_low/mode/high, "mode",
  P10/P50/P90, seed, iterations, std, effective_date. The Assumptions tab
  mentions a "table above" that does not exist and a `--pto` CLI flag.
- **The Inputs "Used by" column** names CLI commands, and is wrong about what
  the TUI reads (`workspace.py:63-104`).
- **Forecast settings (Year, PTO, Iterations, Seed) are session-only** and never
  saved. The box is titled "Assumptions", which clashes with tab 5. budgie.yaml
  cannot be opened from the TUI.
- **The Plan form traps focus:** Escape does nothing, the digit keys type into
  fields instead of switching tabs, and the footer goes blank.
- **Errors look like successes:** the status line is always `$success` green.
- **The footer is truncated:** at 140 columns "Quit" is cut off, and at 80
  columns tabs 3-5 and q are gone. The footer is the same on every tab, so on
  the Plan tab "e Edit input" and "d Delete project" read as row actions.
- **The scaffold is incoherent:**
  - the year is hard-coded to 2026;
  - shadowed files that do nothing are written;
  - sample weekly.csv spend drives the first forecast;
  - a banner and INFO paths bury every command's output.
- **There are two `pto_days` columns**, in people.csv and allocations.csv, and
  they can disagree.
- **Docs have drifted:**
  - the README says `team.csv`;
  - the README example (4 people, $712k) does not match `init` (2 people, $425k);
  - `budgie assumptions` describes the pace as a straight line, which is no
    longer true;
  - guide step 2 calls people.csv and allocations.csv the key files.

### Polish
- The Changes column hides the year (`Jan 1→0.9`).
- The Projects tab has an unlabelled `→` column, an unexplained "8/8", and an
  80-column path.
- P10/P90 are almost invisible (dark green on grey).
- The clock in the title bar only updates on recalculate.
- At 80 columns, "Add row" and Recalculate are clipped.

## The model Budgie should teach

1. **Who and when:** each person's FTE from a date. `plan.csv` is the only
   place FTE lives.
2. **Rate:** what an hour of each person costs, and how sure we are of their
   hours. `people.csv` holds the rate and the low/likely/high spread.
3. **Time:** a full-time year is about 1,992 h, minus PTO. FTE × that, day by
   day, gives each person's hours.
4. **Cost:** hours × rate, plus non-labour costs. P50 is the expected cost; P90
   is what to reserve.
5. **Reality:** readings (`weekly.csv`) replace the past. Only the rest of the
   year is forecast.
6. **Will we run out:** headroom = budget − (spent + remaining forecast). The
   stoplight is the chance that headroom goes negative.

## Proposed work, in order

**A. Safety and quick fixes (bounded, now).**
- Scope `d` to the Projects table.
- Make `e` open the file the current tab shows (Plan → plan.csv).
- Show errors in red.
- Let Escape leave the Plan form.
- Warn on unknown or mis-cased names.
- Bound FTE.
- Add a "SAMPLE DATA" banner when no project is chosen.

**B. One model (architectural, needs a decision).**
- plan.csv sets each person's hours.
- people.csv keeps the rate and the uncertainty spread around the plan.
- allocations.csv loses `fte`.
- The TUI Forecast is built from the same Snapshot as the CLI and perch (costs,
  budget, readings), and leads with budget · spent · forecast · headroom ·
  stoplight.
- This changes the numbers and the perch contract.

**C. In-TUI plan editing (architectural, the user's ask, builds on B).**
- One table row per plan line.
- Enter edits it in a small form.
- Delete removes it, with a confirmation.
- `a` adds a row.
- Staged changes show a before → after of hours, cost and headroom (via
  `Snapshot.what_if`, the engine `perch cut` already uses), then commit.
- Decide how "fix a mistake" (rewrite the line) relates to "re-plan" (append a
  dated row).

**D. Teaching (bounded pieces).**
- Plain labels in place of code names, with a one-line meaning per field.
- A `?` help screen with the vocabulary.
- A per-tab hint naming which file answers which question.
- A coherent scaffold.
- One-line CLI errors with file and row.
- Quiet output.
- Fix the docs drift.

**Out of scope as disproportionate:**
- a general spreadsheet grid;
- a generic undo stack;
- a separate "what changed" view. The plan's dated rows plus the before → after
  view cover that.
