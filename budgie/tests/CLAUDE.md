# budgie/tests — testing notes

- `display_startup_message` prints the banner as pyfiglet ASCII art, so the literal string `"Budgie"` does not appear in output — assert on exit code / rendered content instead.
- Sample data: `budgie/tests/team.csv` (forecast input), `budgie/tests/team_lean.csv` (3-person variant), `budgie/tests/allocations.csv` (FTE/email input), `budgie/tests/actuals.csv` (monthly actuals), `budgie/tests/scenarios.yaml` (scenario-compare config). **These double as the no-project fallback the CLI ships**, so changing them changes what a first-time user sees. **They tell one story**: four people whose `fte` in allocations.csv/plan.csv equals their `util_mode` in team.csv (so allocated hours = forecast hours, 6,833), spent hours at roughly linear pace, budget.csv 800k/850k/835k against a ~794k labor+non-labor forecast. The `init` scaffold has its own two-person version of the same story (Alice 0.90, Bob 0.85, budget 425k/450k). Change one file and the others need to follow, or `forecast`'s estimate at completion and `hours` start disagreeing for no reason.
- `test_startup.py` (import weight; runs in `tmp_path` because the landing screen looks for a project and finding one changes what gets imported. It compares **full** module names — an earlier version compared top-level names only, which made its `budgie.core` assertion vacuous)
- Workspace-touching tests must call `forget_workspaces()` — `find_workspace()` is cached, and `tmp_path` changes between tests. `test_workspace.py` does it in an autouse fixture.
- **Anything that prompts must monkeypatch `budgie.budgie._interactive`.** `CliRunner` replaces `sys.stdin` wholesale, so patching `sys.stdin.isatty` patches the wrong object and the prompt never appears. Without a terminal both `init` and `delete` take their non-interactive path, which is the behaviour you want in CI but not what a prompt test is trying to exercise.
- **Discovery tests are sensitive to what's *above* `tmp_path`.** pytest puts sibling test directories next to each other, so a walk-up that isn't bounded finds other tests' projects and reports them as candidates. That is exactly how the unbounded `available_projects` version was caught — if a discovery test fails with project names from an unrelated test, the search widened, it isn't a flake.
